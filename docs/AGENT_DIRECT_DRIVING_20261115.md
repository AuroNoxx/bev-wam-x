# 由助手观察数据、逐步决定驾驶动作的演示

2026-11-15。用户明确希望助手根据场景数据自行驾驶，而非把自车交给 CARLA Traffic Manager。此次已经按这个分工执行。之前的 TM 初筛不能代表助手本身的驾驶决策表现。

## 实际分工

- 助手每次读取自车速度/车道/位置、各车道前后车辆间隙与TTC、其他车辆速度，再通过工具下达目标车道、目标速度及2–3秒仿真执行时长；每条指令保存理由。
- 自车始终关闭 autopilot，未注册到背景车辆的 TM 控制中。底层新桥接脚本只执行外部指令：道路参考线、五次平滑变道曲线、Pure Pursuit 与速度PI；没有“第几秒超车”的行为计划。
- 四辆背景车辆仍由 TM 控制。地图和车辆状态是特权真值，不是 OCC/RGB 观测，更没有加载 Flow 或世界模型。
- 等待工具调用和助手判断期间，CARLA同步物理时间不前进。回放只含物理推进，不含思考等待，不能当成实时推理性能证据。
- 变道前保留间隙/车道线检查；执行中设近距/TTC紧急制动保护、道路联合范围检查。此次紧急保护没有触发；不因此宣称保护完善。

## 决策与结果

20条运动指令、57秒模拟，约801米，最高79.93 km/h，最后停至0。

1. 起步观察：中间车道，自车静止，前车净距55米；选择平缓加速40 km/h。
2. 观察前车44.4 km/h后选择45 km/h跟随；再观察左侧间隙，逐步提速60。
3. 第15秒观察：左前218米、左后88米，前车44.5、自车57 km/h；助手决定左变道。执行后先保持60，等待横向过冲收敛至约3厘米，再加速80完成超越。
4. 第29秒处于与原前车并排状态，助手选择保持左车道，不回切；第34秒原前车净距已在后方46.9米、后向时距3.79秒，才决定回中间车道并降到70。
5. 第40秒已经回到中间车道，原前车落后93.8米。继续观察后，第43秒弯道横向偏差约0.79米，助手主动选择降至40；第49秒实际39.93 km/h，偏差降至0.18米。
6. 观察后车尚有132.8米间距，结束有限场景，保持车道平缓减速停车；第57秒0 km/h，随后销毁自建车辆/传感器、恢复世界设置。该结束动作只为仿真测试，不是正常道路行程的停车策略。

本次无碰撞，紧急保护介入0帧。但**不作为合格专家轨迹验收**：

- 进入缓弯后车道中心误差最大0.849米，可能使车身部分侵入相邻车道；道路联合范围不等于目标车道保持，不能宣称“全程没有越线”。
- 首次左变道存在约0.48米过冲；底层跟踪控制器未完成车型/速度标定。
- 速度差分加速度绝对值P95约2.02 m/s²、峰值3.50 m/s²；本次场景、前车行为与之前TM急减速场景不同，不能直接把差值归因于控制器改善。
- 仅一段开发场景，没有危险切入、封堵后的取消、0–120覆盖或泛化评估。没有在未知观测下驾驶。

此次证明的是：**助手可以依据新的实时场景数据逐步决定行为，并通过自己的执行器在CARLA中完成一次跟随、变道、超越、回切和停车。** 它不证明LLM已达到专家质量或实车实时性。

## 实现和证据

- `scripts/agent_drive_bridge.py`：独立控制桥接；启动后暂停等待外部命令。速度限制0–80 km/h，单条命令最多3秒模拟，空闲240秒结束会话。
- 从实际车辆物理参数测得轴距2.875米、后轴相对actor原点约-1.437米、前轮最大转角35度。UE5 `wheel.location` 是世界米坐标，转换到车体后计算；初版旧API属性错误发生于驶动前，失败日志保留。
- `logs/agent-drive/20261115-182205/decisions.json`：全部20次指令、理由、当时自车状态。
- 同目录 `telemetry.jsonl`：20Hz实际运动及控制记录；`assessment.json`、`report.json`：结果；`source-sha256.json`：脚本指纹。
- `agent-drive-4x.gif`：114帧、4倍速回放，标注决策编号、车速、车道和偏差；原始PNG保留。
- `logs/agent-drive/20261115-182019/`：驶动前API适配失败记录，未覆盖。
