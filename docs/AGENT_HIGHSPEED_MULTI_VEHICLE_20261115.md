# 九车高速连续交互测试，2026-11-15

完成了一次 29 秒、约 943 米的连续跟车、左变道、超车、返回原车道测试。不是已训练 Flow 模型的闭环成绩，也不是专家资格认证。

**评估定位更正：本次仅为已知交通布置下的控制器与动作流程调试，不计入未知交通驾驶能力评估。** 用户要求其他车辆独立驾驶；本次由同一个助手指定背景车位置、目标速度并关闭自主变道，又承担自车决策，不满足该要求。零碰撞和动作完成是这次运行的事实，不能据此声称通过了独立多车交通测试。原始结果保留，不作删除或改写。

后续独立交通测试约束：

- 交通生成端与自车决策端分开。生成端按事先固定的道路、车流密度和交通行为分布运行独立背景驾驶策略；不为促成自车超车而逐车安排配合动作，也不在看到自车表现后改配置。
- 自车决策端只接收截至当前时刻的观测历史和自身导航，不接收背景车目标速度、路线、行为参数、随机种子或未来动作。仅把配置隐藏在同一脚本里，不能声称已完成这种隔离。
- 独立背景策略需允许自主跟车和变道；现有 Traffic Manager 在本项目高速变道诊断中存在失败记录，开启开关不等于已经验证具备所需行为。先检验背景交通行为，再决定使用何种策略。
- 运行前固定评估时长、失败和任务判据，保留所有运行。不能以同一场必然出现并完成超车为通过要求；没有安全机会时应允许继续跟车。需要专项交互覆盖时另列场景覆盖测试，不能冒充盲测。
- 测试结束后才读取完整背景配置、种子和真值作审计。随机化本身不等于独立性，也不等于交通真实性。

上述为修正后的测试约束，尚未实现或运行新的独立交通测试。

## 执行方式与场景

- CARLA 1.0 UE5，Town12，road 388 的三条连续 3.5 米车道，白色 Tesla Model 3 为自车。
- 共九车。前车目标 100 km/h；左侧两车 130；右侧三车 105；同车道后车 100、远前车 115。记录前一次性初始化速度，之后正常物理仿真，无中途位置/速度覆盖。
- 自车 autopilot 始终关闭。助手根据当前地图、车辆真值状态，逐次下达车道和目标速度，Pure Pursuit + 速度 PI 在 20 Hz 执行；背景车辆使用 Traffic Manager。共 12 次决策，决策之间仿真暂停。
- 输入是特权地图/车辆状态，不是 OCC 感知，也没有调用 Flow 或世界模型。RGB 仅用于回放。
- 当前场景不含突然切入、紧急制动、弯道或传感器遮挡；有快车从侧后方通过、右侧车辆占道及并排行驶。作者知道布置，属于开发测试。
- 未修改默认天气；运行后读取云量 75、降水 0、湿度参数 wetness 0，详见 `runtime-after.json`。画面阴天不等于雨天测试。

## 先发现的错误及最小修正

未补偿转向曲线的独立预检，在 10.55 秒、约 128 km/h 左变道时触发车身越出指定车道走廊，立即终止。证据保留在 `logs/agent-drive/20261115-203026`，包括原始代码、配置、车辆物理参数和逐帧日志。

读取车辆得到最大轮转角 35 度、轴距约 2.875 米，转向可用比例在 120 km/h 及以上为 0.30。旧控制器按完整最大轮转角换算归一化 steer，漏掉速度缩放。CARLA 官方文档定义曲线横轴为 km/h、纵轴为可用转角比例：https://carla-ue5.readthedocs.io/en/latest/tuto_vehicle_physics/ 。

仅增加按实车曲线插值的转向输入补偿；没有更改车辆物理、纵向控制、变道曲线、保护阈值。该补偿通过场景开关启用，旧场景默认行为不变。道路/车道参数化用于新的直线路段，旧 helper 默认 road 1157 不变。

相同初始条件、相同前四条指令复测，通过原失败时刻，随后完成返回变道。20 秒预检最高 129.77 km/h，变道状态之外最大中心误差 0.067 米，零碰撞、零越界、零保护。证据 `logs/agent-drive/20261115-203207`。这支持本次错误修正有效，不证明所有高速控制工况都已解决。

动作依据：

1. 0–8 秒保持中间车道跟车。3 秒时左快车仅在前方 8.64 米，6 秒时 31.19 米，均不变道。
2. 8 秒左车已拉开 46.19 米且继续远离，左后方无车，开始左变道并平滑加速。14 秒变道已完成，自车 128.20 km/h。
3. 17 秒与原前车并行；20 秒虽已超过，但后向净距仅 22.13 米，继续左车道等待，不强行切回。
4. 23 秒原前车后向净距 46.40 米、对应后车时距约 1.70 秒，开始返回中间车道。
5. 29 秒返回完成，中心误差约 0.017 米，右车道另有一车并行。到达预定时长即结束记录并销毁本次车辆，不表示完成停车。

## 证据和局限

- `decisions.json` 保存每次理由和当时全部车辆状态；`telemetry.jsonl` 保存 20 Hz 实际运动；`report.json` 保存碰撞、车道线和保护事件；`assessment.json` 与 `task-evidence.json` 保存统计。
- `bridge-source.py`、`helper-source.py`、`scenario.json` 保存实际运行版本。`replay-4x.gif` 是 4 倍速回放，原始图像为 2 Hz。
- 每帧检查自车四角位于指定驾驶车道联合区域；碰撞传感器覆盖全部九车。车道线虚线跨越是预期行为，不计为车道越界。
- TTC 按同 road、同中心车道的纵向 s 和车长计算，不是连续扫掠碰撞证明。变道时决策同时查看起点和目标车道，但紧急保护仍主要依赖当前中心车道。跨 road 的车辆会从这类间距统计中排除。
- 相邻车道的纵向区间重叠是正常并排，不能把其 TTC=0 解释成碰撞。本次终点回放已检查：自车中间车道、蓝车右侧并行。
- 仿真在助手思考时暂停，不能证明实时反应能力；九车数目不等于九车都在同一近距离内。暂无随机种子重复、雨雾分层、强制切入、拥堵、弯道或紧急制动验证。
- 本次没有训练、改权重、删除旧结果，也未改变固定模型架构。作为专家候选的下一步是批量重复和失败场景验证，先不能直接混入正式专家训练集。
- 本轮三个运行累计约 59.55 秒仿真；日志、原始画面及回放共约 55.42 MiB。仿真按 20 Hz，助手决策暂停导致墙钟时间明显更长。退出后车辆数为零、世界已恢复异步模式；模拟器可见窗口保留。
