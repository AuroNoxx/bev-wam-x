# 接手审计与轻量对照（2026-11-15）

结论：保持追加训练暂停。没有证据支持现在直接采用“按速度缩放 OCC 范围”；先解决时间契约证据链和可执行性评估缺口。当前仍是公开历史 OCC＋车辆状态＋导航的离线规划器，不是 RGB 感知闭环。下面区分实测、源码事实与尚未证明的判断。

## 1. 现场状态与保留边界

接手时训练进程已结束，`logs/stage1-v2/stage1-launch.json` 为 completed/exit_code=0；只有本地 TensorBoard 运行，未发现引用本项目的 Windows 计划任务。没有终止其他项目或 TensorBoard。

新增 `configs/TRAINING_PAUSED.json`，并在 `run_stage1.py` 启动器最前面检查它；实测 `--resume` 会在读取数据/启动训练之前拒绝。此标记约束原追加训练启动器，不是操作系统级锁；直接手工调用底层 trainer 仍可能绕过，审计期间不要这样启动。未改变 Trainer、优化器、断点实现、数据索引、缓存、损失或模型结构。未运行长训练，世界模型和 CARLA 没有启动。

`preserved-files.json` 记录接手时 50 个断点/JSON 结果文件的 SHA256，结束复核全部一致；包括原版和 v2 best/latest、旧评估与测速结果。新的回归基线拟合参数和诊断结果均在独立 diagnostics 目录，不覆盖训练断点。正式测试集仅保留清单元数据，未打开其样本或计算指标。

CARLA 文档规定传感器局部坐标 x前/y右/z上、IMU加速度 m/s²、陀螺 rad/s；当前符号转换与此一致。[CARLA传感器文档](https://carla.readthedocs.io/en/0.9.15/ref_sensors/#imu-sensor)。尚未校准 IMU 安装姿态、导航坐标与运行时姿态来源的偏差，不能把单次位姿复算当作整个契约已验收。

**编号生成链没有完全查明。** 9条验证路线均出现 OCC=-1 起、标注=0 起，以及各自末尾差一文件。缓存 `prepare_route` 按整数同名交集配对，因此丢弃 -1 OCC 和最后一个标注。固定上游代码 revision `7ec25d1c9f7522d923ce5f3420986cef1cb2d956` 的 `tools/data_collect.py` 在 save 内使用 `frame=self.count` 保存 RGB/标注，但该公开文件没有调用 OCC 保存器；只有 expert_assessment 明确使用 frame-1，不能拿它推断 OCC 的逻辑。GitHub API 查询遇到 rate limit，随后通过只读 git refs 和固定 revision raw 文件完成代码检查；没有因此猜测或改索引。

**偏移的实测支持较强，但仍属于待确认。** 每条验证路线均匀取12时刻，共108；其中18个自车速度<0.5m/s、90个移动时刻。动态探针有104个有效时刻，排除近自车区域，把源车辆体素与对应时刻车辆包围盒比较（外扩0.3m，容忍体素/表面差异）。静态探针把相邻帧静态体素用候选位姿对齐，再在共同非255区域计算IoU。

## 3. 类别、mask 与四种覆盖

| 语义 | 文件/代码中的实际表示 | 能否作为安全空地 |
|---|---|---|
| 占据 | 源occ=1；seg映射到缓存1…7 | 含语义LiDAR、历史融合、包围盒/地面填充，不都是当前直接可见表面 |
| 确认空闲 | 当前源文件没有独立可靠的射线可见/空闲mask，也没有对应缓存类别 | 不能由occ=0或非255推出 |
| 未观测/遮挡 | 源occ=2可表示缺输入/unknown；缓存255还用于越界 | 正常遮挡区域并不保证编码为2；不能把255当成完整遮挡mask |
| 源未填充 | 源occ=0→缓存0，名称明确 not_verified_free | 原生成器初始化为0，不能证明它经过空闲射线验证 |

抽查108个源OCC只有0/1，没有2。当前编码器把255映射为第9个embedding，与0严格分开；世界模型对255使用ignore_index。**没有找到显式 unknown→free 的重编码，但系统缺少区分“确认空闲”与“未填充/遮挡”的充分数据，不能声称mask问题已解决。** XY池化优先保留占据，mixed unknown/occupied块会丢失子体素可见性，不能解释为整个0.8m块都已观测。

当前画布 x∈[-25.6,102.4)、y∈[-25.6,25.6)，其中当前帧非255只占40%；前方25.6m外非255比例为0。验证集当前占据27.484%、source_unfilled12.516%、padding unknown60%。这三个数的分母是整个20×64×160画布。

历史各帧在当前坐标的非255覆盖均值为36.700%、37.655%、38.732%、40.000%；四帧并集40.006%。历史不是把视野简单乘四，也没有补出远处真实观测。未来OCC标签1…5秒非255分别39.155%、38.817%、38.461%、38.057%、37.568%，它们来自未来自车附近观察窗经位姿变换，不能冒充当前观测。

轨迹标签则由位姿生成：28100个验证未来点里8371个（29.790%）超出当前原OCC前向25.6m，落在841个窗口中；这些标签并未因为超出范围而失效。轨迹覆盖、源栅格范围、历史并集和传感器视野是四件不同的事。

**传感器与远距支持：** 标注实际有车顶LiDAR、位于前后约20m的额外语义LiDAR、六相机、Radar；抽查两个压缩包包含 lidar/lidar_seg/radar/RGB，但没有另一个大范围 OCC。公开采集器写有LiDAR range=85m、Radar=100m，不过该文件缺失新版 OCC/辅助传感器采集部分，不能据此认定这些参数完整对应此次数据。相机角视野也不是可测距离。当前没有查到本地同帧、同标定、远距且带可见性mask的 OCC 真值；原始远点回波是否足够重建，必须进一步逐点核验。额外前后置语义LiDAR与包围盒填充带来特权信息，不能等同于拟部署传感器能力。

## 5. 最小后续实验与停止条件

按以下顺序，每次只改变一个因素；本轮没有启动这些追加训练。

|---|---|---|---|

## 6. 架构选项与取舍

架构顺序继续遵守 OCC→Flow带时间轨迹→执行可行性→轨迹条件世界模型→评分→Pure Pursuit＋速度PID，不增加RGB感知训练或独立BEV分支。

| 方案 | 优点 | 代价/数据要求 | 当前意见 |
|---|---|---|---|
| 固定物理坐标＋速度/路线/目标风险加权关注 | 轨迹/历史/地图坐标一致；近场与侧后方不被缩放；只改注意权重或候选评分 | 需校验关注变化不会掩盖侧后方切入；不知道的区域仍unknown | 契约清楚后首选轻量对照，先不动输入网格 |
| 固定近场细、远场粗 | 保留近场精度，远处减少密集计算；后方/侧方完整保留 | 必须有真实远距观测及监督mask；尺度间warp/边界需校验 | 数据补齐后优先比较 |
| 按速度动态范围/分辨率 | 高速可把更多算力放前方 | 固定cell数扩域会降近场精度；历史要重采样，模型需范围/原点/尺度条件；保持分辨率则算力增加；速度跳变要防止坐标抖动 | 保留为备选，现阶段无证据优于固定多尺度 |

当前4×20×64×160历史张量819200个标签；其中60%当前帧是前向扩展padding。仅以体素数估算：近场保持0.8m的20×64×64，前方25.6–102.4m用1.6m的20×32×48，共112640体素/帧，为当前204800的55%。这不是实测运行时间，双分辨率编码、拼接和attention仍有开销。若近场改0.4m，会增加到至少327680体素/帧，不能同时声称更细且更省。所有例子保留±25.6m侧后区域；远区unknown不能当新增观测，预测未来也不能当真实传感器输入。

**需要的数据：** 同tick远距原始回波/深度与标定、逐射线确认空闲/遮挡mask、可观测范围与观测年龄；对应远距OCC真值及构造过程；地图车道/可行驶多边形、车型外形/动力学/制动与控制延迟；涵盖90–120km/h及制动、切入、取消变道的独立训练数据。先验证现有lidar/lidar_seg的远点范围、实际传感器位置和文件同步，能复用则复用，不盲目下载或扩大网络。

## 7. 世界模型审查与CARLA闭环计划

当前 `TrajectoryWorld` 只接受历史OCC、状态和25点条件轨迹，训练条件为实际专家轨迹；未来标签由同一条日志生成。没有同初始状态多候选行动及周围车辆不同反应的成组数据。现有world目录主要是测速结果，没有已通过候选动作反事实评测的正式世界模型。早期world测速版本和当前正式契约不同，不能用其loss推断当前模型已具备能力。

输出是8类logits；没有独立有效覆盖/可见性输出，没有已经校准的不确定性模块。ignore_index=255只是不计算某些标签loss，不会让模型在未知区域自动保守。类别0仍是unfilled，softmax置信度不能证明已知空闲。候选偏离专家、执行跟踪误差、大速度、unknown-heavy输入都可能OOD；真实未来轨迹条件与实际可执行候选条件也存在分布差异。**现在不能把该模型当作安全裁判。**

最小反事实数据计划：20个初始场景×5种动作分支（维持/制动/合法左变道/合法右变道/取消，按初始条件过滤）×3个交通随机种子×5s，约1500模拟秒。必须重置同初始场景并核验actor位姿/速度和信号状态容差、让其他车辆真实响应，日志坐标平移不算分支。分支同根必须在同一split。先记录实际执行轨迹、未来动态OCC、传感器可见性和碰撞事件，少量探索后按失败类型增补；无效分支与碰撞也需保留，不伪装成功数据。

评估需包含各时距动态占据精度、可见区/未知区分层、分支间差异、风险事件召回与误报、Brier/NLL/可靠性曲线；使用独立校准子集，不拿保留测试集定阈值。ensemble/重采样或显式概率模型可研究，但先证明校准；OOD包括候选轨迹偏离训练分布、速度超支持、低覆盖和高执行误差。无法判断时拒绝评分/回退，不用一个低离线loss消除硬约束。

CARLA闭环按三步推进：先核对当前引擎/地图与数据类目，并单独标定Pure Pursuit＋速度PID的转向符号、延迟、制动/转角极限，在预定义直道/弯道/停车轨迹上测跟踪误差；随后用与数据生成契约一致的几何OCC闭环运行Flow＋可执行性＋规则评分，先不使用world；最后固定候选、相同scenario/traffic seed，比较有无world评分。

首批建议6场景（巡航、跟车制动、切入、合法变道、超车、取消变道）×3种子×2选择方案×60s，共2160模拟秒。规划5Hz/控制20Hz，记录延迟p50/p95/max、超时、回退/接管、路线完成度、进度、碰撞事件与严重度、驶出道路、非法越线、实际速度/加速度/jerk、跟踪误差、unknown暴露与失败案例；变道过虚线不自动算失败。以同episode统计，不把高度重叠窗口当独立驾驶里程。任何高速测试要等实际传感器有效视距与制动能力支持，当前数据最高43.5km/h不够。

成本：反事实1500秒和闭环2160秒分别至少需要25/r与36/r分钟模拟运行（r为本机实测模拟秒/墙钟秒），另加启动/重置/保存。尚未实测当前场景r，不能给确定墙钟小时数。数据量先以一个60s片段实测每帧字节，再乘帧数；不预报虚假的小容量。世界模型旧测速约57.9 samples/s只供预算参考，当前配置必须重新短测速，不能当收敛或反事实有效性的证据。
