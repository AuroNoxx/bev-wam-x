## 任务与边界

保留工程成果和历史成败，建立独立版本的BEV联合世界—动作模型。主链应为：

历史BEV、自车运动/历史动作、导航 → BEV时空编码 → 在同一预测器内联合生成未来latent和驾驶轨迹 → 统一执行检查 → 控制器 → 新观测。

未来场景token与轨迹token须在生成过程内交互，且有清晰的联合训练与梯度设计。只共享encoder、加两个独立头，或先生成轨迹再让WAM评分，都不能当作完成方法对齐。当前旧JointModel已经使用预测未来特征，不要错误报告成“旧模型完全没耦合”；差异在联合生成机制、训练目标与时间跨度。

保持以下项目约定：

- BEV为128×128、四通道CHW uint8、覆盖64m、自车居中且车头朝上。
- 输出10个(x,y,v,heading)路点，间隔0.2s；控制10Hz。
- 完整系统参数50M–100M，目标60M–80M；完整决策P95≤50ms。参数预算是共享编码器＋联合预测器等实际推理模块的总量，不能将旧75M WAM再强制叠上去。训练EMA开销另算。
- 仅PyTorch ROCm和原生functional SDPA；不引入flash-attn、xformers、Triton、自定义CUDA算子或torch.compile，不硬编码某块GPU的规避补丁。
- 独立实现；可以读论文方法，不使用WA-JEPA/V-JEPA代码、克隆、训练数据或预训练权重。
- 原始数据、旧源代码、历史报告、有效和失败实验记录均保留。schema1数据不能恢复为新训练数据；无效融合001不能混入训练或通过统计。
- 导航、静态许可、车型等额外输入各基线匹配。仿真交通真值只用于明确标注的老师/评估，不能偷渡到模型推理输入。
- 不启动已知失败的同进程Panda3D/Pygame live路径。用公共`RerunLogger`；Rerun时间轴不是手动驾驶控制。

2. 归档旧规格；更新GOAL/AGENTS/计划当前部分，保留原文字与来源；更新TASKS。
3. 固定历史时刻t−0.3/−0.2/−0.1/t；建议未来BEV为t+0.5/1/1.5/2秒，轨迹仍t+0.2…2秒。说明未来BEV使用各时刻自车坐标，而轨迹使用当前自车坐标；任何改变单列版本。
4. 明确历史运动与实际控制字段、mask、终止规则、episode边界；n+1状态不代表n+1个BEV，不得伪造最后未来帧。

### 阶段1：基础接口兼容性回归

复用原EGL/BEV验收，只针对改动重测；检查控制接线、请求/实际动作、坐标、车型、时间对齐。修正旧短测：先实际加速，再按[steering,throttle]正确制动、停车和重新起步；覆盖运动中遇险与弯道。对终点和车道许可做原生最小复现，再决定是否修代码，不能先放松阈值。

### 阶段2：新样本与公平基线

优先审计并复用009/010有效原始episode，构造历史BEV、历史动作/运动、当前导航、4未来BEV、10点轨迹与各自有效位。冻结latent缓存不能作为新可训练encoder的目标真值，训练须访问原始BEV。世界预测与动作模仿资格分别mask，事故和诊断轨迹不能自动成为好动作示范。

按缺口补常规导航、跟停/再起步、左右超车回归、阻塞等待、恢复和终点数据；统计独立场景而非只报帧数。训练同输入MSE/ResNet基线，先建立真实小规模闭环。所有新数据独立目录和schema/manifest，不覆盖旧数据。

### 阶段3：BEV未来生成预训练

实现BEV历史条件、多时刻未来Flow预测、线上encoder和EMA目标encoder。先严格历史条件分支，验证后加入训练专用未来patch补全分支。BEV卷积stem可能跨patch传播信息，避免“先编码完整未来再遮token”造成泄漏。

旧stage3/4权重可作可选初始化，不永久冻结；VICReg是否保留、作用在哪个表示上作为明确设计。训练目标与采样公式必须一致，物理时间与生成时间分别编码。

检查无未来泄漏、教师更新、mask与梯度，报告逐时域误差、copy-current/匹配确定性基线、动态/边界子组及表征健康度。不同编码空间的裸latent MSE不可直接作优劣排名。生成模型的oracle-best误差只能诊断，不能作为部署成绩。

### 阶段4：联合未来—轨迹生成

用带噪未来场景token与带噪轨迹token进入共享交互预测器，每步联合更新。明确非对称梯度：场景损失到动作token的阻断与动作损失到场景表示的可微路径；写实际梯度测试，不凭结构名称宣称实现。

完成稳定冒烟和资源校准后，逐步联合微调encoder/预测器，EMA对应更新。保持显式(x,y,v,heading)输出，检查速度/位移/航向一致性。

至少准备四个同数据/输入/控制/调参预算的主对照：A确定性轨迹，B Action-only Flow，C分离式未来预测＋动作生成，D联合未来—动作Flow。D再做移除未来监督消融。至少两独立训练种子；采样噪声种子不能冒充训练重复。报告实际参数与计算量，必要时匹配容量以隔离结构收益。

先做导航、弯道、跟车闭环；不同时新增独立75M WAM、风险头、规则超车状态机或新的控制空间生成器。通用安全检查各臂一致，原始输出/干预后输出/实际动作分别记录。

### 阶段5：新版退化压力评估

复用遮挡/边界/丢帧框架，对冻结新版与匹配基线重测开闭环。先只退化观测，未来监督/真值保持正确。需要退化训练时另开对照，不边测边适配。旧成绩不继承。

### 阶段6：联合模型后果一致性

利用原生分支回放，执行生成轨迹，验证与其配对的预测future；将控制跟踪误差、模型预测误差和终止mask分开。持续重规划的执行不是原两秒固定命令的反事实真值。

联合分布不自动等于任意动作干预模型。若需要指定任意动作预测未来，单独冻结条件训练/inpainting扩展并用真实分支验证。旧独立WAM/风险头仅作历史对照，不自动接回主链或复用旧阈值。

### 阶段7：完整融合驾驶

逐类验证导航与终点、弯道控速、跟停再启动、超车回归、阻塞等待、恢复与混合行程。模型生成动作；若加规则行为或解析候选，单列增强臂，不能归因为模型学会。

015反例用于回归，独立开发场景用于泛化。报告到达、安全、效率、无故停车、干预率与世界增益；按独立场景/seed配对统计。完整决策P95包含预处理、encoder、联合采样、选择/检查和控制输出，另测采集/仿真/日志与10Hz调度。禁止使用head-only计时验收。
