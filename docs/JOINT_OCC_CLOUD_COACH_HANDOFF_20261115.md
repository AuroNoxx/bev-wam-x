## 目标与取舍

采用 OCC 输入以降低复杂度，不换 Qwen 视觉头，不新增 RGB 感知训练。借鉴联合未来表征与动作生成思路，不声称复刻小鹏私有架构。历史 OCC、当前自车状态、导航经过共享空间/因果时序主干，联合训练 JEPA 式未来表征预测与 Flow Matching 轨迹生成；先有共享主干辅助损失对照，再比较 Flow 显式使用模型预测未来 latent 的融合版。JEPA 目标编码器 stop-gradient/EMA，并验证防坍塌。不要将 Flow Matching 误写成语言模型，也不要把 PID 当作学习模型自身的完整动作头。

## CARLA 与早期云端 LLM 教练

初始学习后进入 CARLA 闭环自探索，从简单低速停车/跟车逐步到车流、变道与高速。不要将历史离线日志当成能提供任意未执行动作的真实后果。当前历史完整窗口最高速度不足 60 km/h，不据此宣称高速能力。

程序化指标负责碰撞、道路/车道合法性、安全间距/TTC、车辆动力学、目标进度、速度和舒适度；安全约束优先，不能让 LLM 高分覆盖碰撞或违规。安全超车不是无条件奖励，保持合理安全距离也不应变成永远停车刷分。

云端 LLM 从早期闭环就参与，不只是最后打分：对结构化场景、候选轨迹和实际 rollout 后果做比较、解释失败、给策略建议；若本地候选全差，允许提出战术或候选轨迹参数。所有建议必须经过几何/动力学检查和 CARLA 验证后才进入数据，不把自然语言建议直接当正确动作，不让云端 LLM 按每个控制 tick 操纵车辆。

实现需明确可执行的训练更新规则：例如通过验证的改进轨迹做回放/加权模仿暖启动，偏好对用于已明确数学目标的偏好优化；先做最小可检验版本，不声称“收到分数就自动训练了 Flow”。保存状态、候选、实际结果、硬约束判定、LLM 版本与评分、筛选理由和更新来源。测本地策略独立表现、教练介入比例与保护接管率，防止只因外部教练接管而虚报进步。
