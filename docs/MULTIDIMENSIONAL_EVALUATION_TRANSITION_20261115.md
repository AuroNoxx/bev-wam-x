# Transition: fitting diagnostics are not driving acceptance

Latest user direction: ADE only diagnoses label fitting, not final good-driving or overall acceptance. Do not reject a safe alternative merely because it differs from the recorded expert. No scalar ADE winner promoted from the probes.

## What is actually measured now
Train-only trajectory label reconstruction/fitting; sampled position/heading/speed internal kinematic consistency; scalar-speed acceleration and jerk summaries; model timing and memory; explicit future-label isolation and input masks. These do not establish collision avoidance, efficiency, comfort, steering feasibility or safety. Current parameterization test is one training seed/four anchors, not a driving benchmark.

## Next measurable layers (planned, not yet integrated)
1. Unified offline diagnostics: metric schema carries source, scenario, speed bin, simulator time vs wall time, candidate index, validity, units and sample count. Report vector acceleration, lateral acceleration, yaw rate/curvature, vector jerk, signed backward speed above threshold, stop creep, steering/actuation bounds and tracking feasibility separately. Thresholds must come from the simulated vehicle/control model, not invented universal limits. ADE stays in a separate fit panel. Evaluate candidates as a distribution, not only hindsight best candidate.
2. World prediction: compare multi-horizon future predictions against persistence and shuffled-target controls; occupied-object motion/vehicle regions, masked semantic quality, visibility/unknown coverage and latent noncollapse. Masks and future labels remain evaluation/auxiliary-only, never actor inputs. Latent MSE alone is not dynamic understanding; missing observable evidence produces unavailable metrics, not zeros.
3. CARLA controlled closed loop: fixed held-out scenario seeds, same controller and traffic realization, paired policy comparisons. Safety constraints first (collision type/severity, off-road/lane-boundary violations, red-light/traffic-rule violations, minimum clearance/TTC with validity, emergency interventions); then completion, route progress and time efficiency; then feasibility, tracking and comfort. Do not reward unnecessary overtaking; safe following can be high-scoring when traffic/risk warrants it. No finite score makes collision acceptable merely for faster progress. Maintain0–20/20–40/40–60/60–80/80–100/100–120km/h coverage separately, acquiring high-speed/interactions later rather than claiming present coverage.
4. Early asynchronous cloud LLM coach: consumes approved structured scene/trajectory/outcome summaries, returns schema-validated rationale, failure taxonomy and candidate alternatives. Mechanical hard checks override LLM preferences. Alternatives must be simulated/verified before entering replay or preference learning. Include evaluator agreement/calibration, contradictions and missing-evidence handling. It is not tick-level control and not sole safety judge. Provider/auth/data-sharing/budget must be confirmed and configured before calls; no cloud calls have occurred here.
5. Learning loop: gate new policy promotion on a vector of required safety/feasibility outcomes and confidence, then compare efficiency/comfort and LLM interaction judgements within feasible candidates. Replay balances speed/scenario types, fixes evaluation scenarios separately and never trains on final test outcomes. Keep explicit policy/data/evaluator versions.

## Execution prerequisites and honest limits
CARLA closed-loop and cloudLLM are NOT integrated by these probes. Before claiming metrics: verify simulator lifecycle, synchronous stepping, sensors/caches reset, collision/route events, controller tracking and episode termination logging; validate metric calculations on scripted safe/unsafe toy trajectories; run an existing rule-based control baseline to exercise the logging pipeline. Only then test a learned planner. When collecting model failures or using heldout results to tune, label that set diagnostic/adaptive and retain a separate final benchmark.

Proposed immediate implementation is metric-contract/unit tests plus a scripted baseline evaluation harness, not more blind capacity or ADE-only sweeps. SourceOCC release causality remains unresolved; label oracle status explicitly and prioritize a causally generated simulation input before any deployment claim. All proposed stages require actual execution evidence before reporting numerical success.
