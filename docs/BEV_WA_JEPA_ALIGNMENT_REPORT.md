# BEV版WA-JEPA方法对齐：分阶段修改报告

日期：2026-10-22（用户时区）。状态：设计提案与源码核对，尚未实施或启动训练。

用户目标：借鉴WA-JEPA的世界—动作联合建模方式，将视觉输入替换为BEV。当前报告据此调整此前偏工程修复的建议。旧阶段验收、失败证据、检查点和数据均保留；本报告不将旧结果改判，也不自动替换GOAL/AGENTS中的执行协议。

**结论：保留阶段1与大部分基础设施，阶段2做数据整备和补采；阶段3、4是必须重新实现并训练的核心；阶段5重新评估；阶段6重新定义，阶段7重建主推理链；阶段8、9尚未开始，不存在“重跑”。**

## 一、此次对齐的含义

WA-JEPA的核心是未来潜变量生成与轨迹生成在共享预测器内部交互；它先做未来预测预训练，再做世界—动作联合训练。未来场景预测也采用Flow，不能把“轨迹用了Flow”当成已对齐。官方材料：[项目方法概览](https://wa-jepa.github.io/)、[论文方法与附录C](https://arxiv.org/html/2608.20974v1#S3)。

本项目的新主链建议为：

> 历史BEV＋历史自车运动/动作＋导航 → BEV时空编码 → 联合预测器迭代生成「未来场景latent、未来轨迹」→ 统一执行检查 → 已验证控制器 → 新BEV。

未来场景与轨迹必须在生成过程中交互，动作损失能通过声明的计算图影响与驾驶有关的场景表示；不能仅共享编码器、并排放两个头就称联合世界—动作生成。风险头和行为规则不再是证明该方法成立的前置主干。

保留128×128、四通道CHW uint8、64m、自车居中朝上；输出保留10点、0.2s间隔的(x,y,v,heading)，10Hz控制。导航和静态许可是项目明确声明的额外条件，各基线相同。BEV编码器、独立训练、预测时间轴和速度输出都是适配项；因此这是**方法对齐的BEV变体，不是仅换输入接口就能继承论文成绩的复现**。

仍遵循独立实现，不使用WA-JEPA/V-JEPA代码、克隆、数据或预训练权重；仅参照公开方法。论文使用的预训练视觉基础无法直接搬入本项目。BEV预训练是否足够必须自己验证。

## 三、阶段0：先冻结方法契约与兼容范围

这是新增准备步骤，不是一轮训练。第一份实施产物应为独立协议，例如`docs/BEV_WA_ALIGNED_PROTOCOL.md`，本次只建议名称，不生成虚假的已冻结协议。

需要固定：

- **时间轴：** 建议保留历史t−0.3/t−0.2/t−0.1/t，未来BEV目标t+0.5/1.0/1.5/2.0，轨迹t+0.2…2.0。场景与轨迹点数可不同，但时间编码、单位和有效位必须明确。
- **坐标：** 初版未来BEV继续使用各未来时刻自车居中朝上的原始观测；轨迹在当前自车坐标系。预测须学到这种视点变化。若改为统一当前坐标的未来BEV，属于另一目标定义，不能混用；真实未来位姿只能用于离线标签构造，不能注入推理输入。
- **历史动作：** 保留实际steering/throttle核验，同时建议从过去实测位姿构造历史轨迹token，避免把控制命令、实际运动和未来轨迹混为同一字段。只用t及以前记录，初始缺失带mask，不用未来差分补历史。
- **模型规模：** 完整推理系统50M–100M，目标60M–80M；共享编码器只计一次，EMA教师/优化器单列训练开销。旧75M WAM不再作为必须叠加的常驻模块。不承诺未测量的P95或训练时长。
- **执行边界：** ROCm/PyTorch原生functional SDPA；无flash-attn、xformers、Triton、torch.compile或自定义CUDA依赖。保持独立实现。
- **协议变化：** 旧deterministic-first用于保留确定性对照，主实验切换为生成式未来预测；EMA/stop-gradient替代旧双分支直接梯度的部分机制。VICReg可作从零训练的正则候选，须独立说明位置和权重，不能声称这是论文原配置。

先做小批前后向、内存与完整推理校准，固定预算后才正式训练。每阶段交报告后停下，由用户确认下一阶段；本报告不授权自动贯穿全链路。

## 四、阶段1：基础环境不用推倒，但控制契约必须再次过关

复用EGL渲染、BEV通道/朝向/尺度、原100局与FPS/RAM/VRAM验收证据。没有改变渲染器时无需为了改模型重采整套阶段1。

增量回归覆盖：实际车型参数、请求动作与applied_action一致、历史时间戳、世界/自车坐标、真实行驶→制动→静止→再起步，以及曲线控制。修正015短测的动作顺序和静止起步问题。终点导航与许可检查的可疑反例先原生复现，再修改，不能通过放宽约束消除失败。

退出条件：新数据接口的时间/坐标/动作检查通过；原故障MRE仍能识别错误路径。若BEV或模拟器配置改变，再按影响范围重测阶段1指标。独立Rerun不等于手动驾驶，保留键盘控制待办与旧原生失败记录。

## 五、阶段2：复用有效原始观测，重建训练样本

当前核对到`mixed_train_010`有48个episode、`mixed_validation_010`有24个，manifest声明schema3.1与control_verified。这足以作为数据适配试点，不能直接宣称足够训练新联合模型；本次未重新审计每个episode的完整字节与覆盖。

数据按用途处理：

| 数据类别 | 建议用途 | 限制 |
|---|---|---|
| 009/010有效BEV、状态、导航、applied_action及事件 | 首批联合模型样本来源 | 先重验hash、时序、实际控制和示范资格；持续复用的验证集只作开发集 |
| 合规schema2原始数据（如仍保留） | BEV未来预训练候选 | 没有导航时不能伪造导航用于有导航动作监督；schema1不可恢复用于新训练 |
| 旧冻结encoder的latent缓存 | 旧对照复现、检查输入输出 | 编码器变化后全部失效，不能当新EMA目标；新训练须从原始BEV编码 |
| 风险014/015与阶段6分支 | 后果诊断、条件覆盖、失败分析 | 危险/诊断轨迹不是优秀动作示范；分组字段修复后再统计 |
| 已声明无效的融合001、缺失/不一致控制记录 | 失败证据 | 排除训练及通过统计，不因为有图像就自动纳入新世界预训练 |

新样本包含4帧BEV、历史运动与动作有效位、当前导航/许可/车型、4个未来BEV及mask、10点实际未来轨迹及mask、原生事件、episode/seed/时间及来源。世界目标使用实际观测；动作目标优先使用符合示范资格的实际未来运动，不能把请求轨迹无条件当成执行真值。

一个已发现的兼容细节：现采集器保存n个BEV，但states有n+1。最后状态不代表一定有对应终端BEV；重建0.5–2s目标时只能使用实际存在的帧，不能跨episode、复制当前帧冒充未来，必须按目标类型独立mask。

补采按能力缺口进行：常规路线/弯道、跟停再启动、允许左右超车并回归、阻塞等待、低速/偏航恢复、临近终点。先做覆盖表，再决定量；时间上相邻的数千帧不等于数千独立场景。事故样本可在明确目的和条件下用于世界/后果研究，动作模仿损失需屏蔽失败或人工扰动段，避免联合模型同时被训练去模仿事故。

重新训练相同输入的MSE/ResNet基线，冻结训练与校准/验证/test的用途。旧测试和已观察场景只作为历史回归集；新test池必须先查所有历史seed清单，再登记，不能仅靠换一个seed起点就宣称独立。

退出条件：逐字段/时间/实际动作审计、有效目标比例及行为支持数齐全；小批数据能过拟合验证代码；基线能在小规模开发闭环实际执行。退出只证明数据/接口可用，不要求阶段2提前完成全部驾驶任务。

## 六、阶段3：重做BEV未来预训练

旧`LatentPairs/LatentModel`主要是单帧→下一帧(+0.1s)确定性预测，并由VICReg防塌缩。新版需要历史→覆盖驾驶时域的未来latent生成。编码器可从有效旧阶段3/4权重初始化，但必须允许适配新目标；是否优于从零初始化另作小规模验证，不能永久冻结为默认真理。

建议实现线上BEV时空编码器、EMA目标编码器及未来Flow预测器；先验证严格只看历史的分支，再加入训练专用的未来patch补全分支，对齐混合预训练思想。未来目标只由教师产生；补全分支不是驾驶推理通路。BEV卷积stem会跨patch传播内容，掩码必须在会发生空间混合前生效，不能先编码完整未来图再遮token而泄露被遮区域。

Flow的noise/插值/clean-endpoint或velocity参数化、loss权重和采样器须冻结一致；生成时间不是物理时间，两者独立编码。建议先做参数化一致性测试，避免训练一种目标却用另一种ODE公式采样。

退出检查：

- 无未来泄漏，EMA更新和stop-gradient实际生效，目标/预测mask正确。
- 逐时域标准化预测误差与copy-current、匹配确定性未来预测比较；不只看全场景平均值。
- 动态区域、边界区域及时间变化单列，检查塌缩、有效秩和预测变化量；区域标记仅离线评价，不注入推理。
- 不同编码空间的裸MSE不能直接排大小。保留同一目标编码空间的受控比较及共同下游任务，健康度只是必要证据。
- 预先冻结随机采样指标与采样数，不以单条示范上的oracle-best成绩替代普通采样质量；不预设Flow每项MSE必胜。

门槛数值和样本量在实施协议中提前确定；旧阶段3的短时通过标准不能原封不动搬到2秒任务。未形成非塌缩、可用的长期未来表征前，不进入大规模联合驾驶训练。

## 七、阶段4：重做联合世界—动作训练，这是改造中心

需要纠正一个容易过度简化的说法：旧`JointModel`的轨迹头已经使用预测未来特征，动作损失也可通过它回传；旧模型并非毫无耦合。真正缺的是**未来与轨迹在共享生成过程里的持续交互**，以及覆盖驾驶时域的生成式未来目标。

新版用历史条件、带噪未来场景token和带噪轨迹token进入联合预测器，联合输出未来latent与10点轨迹，在每个采样步骤更新两者。无需让4个未来时刻与10个轨迹点一一同数，须显式时间编码。部署只访问历史与当前允许输入。

梯度需严格审计：论文对场景预测损失到动作token接口设stop-gradient，而动作预测可以使用可微的场景信息；这是非对称设计，不是简单全模型detach。[论文式13与附录C](https://arxiv.org/html/2608.20974v1#S3.SS4)。自主实现时测试两个方向的梯度路径，并在短暂稳定训练后以较低学习率联合微调BEV编码器，EMA跟随更新。

建议首轮控制为四个主对照：

| 对照 | 用途 |
|---|---|
| A：相同输入的确定性轨迹模型 | 验证基本驾驶和生成模型的实际代价 |
| B：Action-only Flow | 隔离“轨迹生成方式”带来的改善 |
| C：分离式未来预测＋动作生成 | 对照现有级联思路；明确其未来特征注入位置 |
| D：联合未来—动作Flow | 验证内部交互的额外贡献 |

各臂使用相同原始数据、划分、导航、控制器和训练预算，尽可能共享阶段3初始化；参数/FLOPs不相同时明确报告，增加匹配容量的断开交互控制后才能更强地归因架构。D再做一次“移除未来预测监督”的消融，区分联合结构与未来监督贡献。两训练种子为最低初始配置，推理噪声种子不能冒充训练重复。

新主线不先叠加75M独立WAM、3.9M风险头或规则超车状态机。先在正常导航、弯道、跟车上测模型生成的原始轨迹与统一安全层后的执行轨迹，分别记录干预率。世界—动作配对采样后不得将某候选轨迹和另一候选的future拼接。

保留物理一致性损失/通用执行校验作为BEV项目适配，但第一轮不同时引入新控制空间积分生成器，避免把联合结构与物理参数化的收益混在一起；若残差不一致再次成为瓶颈，再做同样作用于B/C/D的独立实验。解析导航参考也须同等给对照，单独报告参考独立性能。

退出条件：原始轨迹可执行性、实际到达/碰撞/越界/停滞及ADE/FDE完整；D相对B/C的收益在预登记配对分析中可判断，模型性能与世界增益分开结论。若基本驾驶不成立或世界增益没有证据，先诊断并报告，不直接扩大到全部行为。

## 八、阶段5：压力测试保留方法，重新测新模型

复用现有遮挡、边界缺失、丢帧强度和Rerun设施，对新阶段4冻结模型与同输入基线重测。首轮保持目标BEV完整，仅退化可观测输入；patch-mask预训练和部署缺帧必须区分。

报告各强度的开环误差、闭环到达/事故、恢复时间、无故停车和控制干预，按场景配对。老阶段5结论不迁移到新模型。若要加入退化训练，另建matched训练对照，不能边测试边适配。此阶段放在小规模联合闭环成功之后，避免给不会正常驾驶的模型增加压力任务。

## 九、阶段6：保留后果验证，取消必须串接独立大WAM的设计

联合生成p(未来表征,轨迹|历史)不自动提供可靠的任意动作干预模型。不能直接把生成轨迹钳成另一条就宣布获得其因果未来，也不能把旧四选一检索定义硬套为新方法唯一门槛。

第一层检查生成配对的一致性：同一真实上下文生成轨迹—future对，按注册控制器执行轨迹，记录实际运动、实际未来BEV与终止mask，比较配对future和实际结果；请求/实现轨迹误差单列。持续重规划的执行结果不能当作执行原两秒命令的真值，受控分支和实际闭环分开。

第二层才是动作条件能力研究：若确实需要任意指定轨迹后果，新增明确的条件训练/inpainting协议，在同场景原生分支数据上训练和验证，比较正确条件、错配条件、无条件。该扩展是额外研究，不是复现联合生成时天然已经具备的能力。

保留旧分支采集与精确重放能力；旧risk head与阈值不加载进新主线，因编码空间、候选分布和训练目标已变。若以后新增风险模块，重新采集/校准，修复is_flow/is_normal，和不加风险的联合模型公平比较。

退出条件：能区分未来预测误差、控制跟踪误差、观测截断和事件后果；任何后果可辨/风险有效的声明都有独立原始分支支持。没有辨别能力时诚实保留失败，不用风险AUROC替代联合驾驶收益。

## 十、阶段7：把联合模型放进完整驾驶闭环

按开发课程顺序验证：常规导航与终点 → 弯道控速 → 跟车/跟停/再启动 → 允许超车与回归 → 受阻等待 → 偏航恢复 → 混合行程。共享同一模型/输入约定，逐类补训练数据，不要求每加一项再造一个专用网络。

模型本身承担轨迹生成。控制器、合法性检查和紧急回退保留；评估中同时展示原始输出、干预后计划和实际动作。若启用规则行为协调或解析候选，单列增强臂并共享给匹配对照，不能用其成功证明模型学会超车。不强制先搭好规则全能系统再研究联合模型。

重点复用015反例：右侧许可/恢复、负速度、终点前停住、风险死锁、错误短测。它们用于防回归，独立开发场景用于检查泛化。推理先使用固定、可复现且不依赖未来真值的样本选择方案；多候选重排序若加入，另列实验，不能靠oracle选最好轨迹。不再为了单纯多样性阈值牺牲驾驶；旧多样性门槛保留在旧协议，新任务的行为覆盖/可执行性指标另行冻结。

完整P95范围包括BEV张量预处理、编码、联合采样、任何选择/安全检查与控制输出；传感器采集、仿真步进、日志耗时另外报告，并测端到端调度。参数只统计实际执行模块，训练EMA另列。重复几何计算可以消除，但采样步数、token数与精度选择须经验证，不能只展示head-only计时。

退出条件：两训练种子的能力、安全、效率、无故停车、干预率及世界增益分别报告，完整P95≤50ms、10Hz调度和50–100M全系统预算有实测支持；阶段7报告后停止。旧科学门槛和失败结果不删除；旧Full-vs-Zero-Risk门槛仅适用于旧架构，新主对照转为联合/分离/Action-only，必须在新运行前登记，不事后换对照宣布通过。
