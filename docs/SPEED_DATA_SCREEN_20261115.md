# 0–120 km/h 数据来源与筛选（2026-11-15）

结论：有现成的高速真实数据来源，不能说“没有数据，只能全部自采”。但本轮未确认任何一个公开数据集可以同时直接满足本项目的0–120实际速度、连续OCC/可靠free-unknown mask、状态导航、五秒轨迹、合法车道以及可反事实交互全部需求。建议保留现有交互数据，先核验真实高速候选，再自采缺口。

## 候选数据源（仅核查官方资料，未批量下载）

1. **ZOD：优先核验真实高速片段。** 作者论文4.2明确报告最大自车速度133km/h，支持存在真实高速记录这一判断；不是“100–120各类场景均足量”的证明。Sequences有1473个20s片段，Drives有29段分钟级记录，提供连续LiDAR、GNSS/IMU、车辆数据。现行序列说明仍仅中心关键帧有完整对象/道路标注，没有可直接使用的完整时序OCC、跟踪和导航/HD-map接口。应先取metadata/OxTS速度清单，查100–120持续时长与道路类型；不能用全数据最高133证明连续传感器子集一定足量。前视120°相机也不等于RGB环视，但本项目不训练RGB，不构成先改架构的理由。原始LiDAR可用于构建观测OCC，语义、遮挡、动态补偿、未来监督和地图导航还需工程工作。官方获取页面有申请/下载流程，本轮未发送邮件或接受新条款。

[ZOD论文4.2](https://arxiv.org/html/2305.02008v2#S4.SS2)、[连续序列说明](https://zod.zenseact.com/sequences/)、[传感器与车辆数据](https://zod.zenseact.com/)、[获取方式](https://zod.zenseact.com/download/)。

2. **Bench2Drive-Speed：中速与指令控制补充，不解决120。** 2100条CARLA场景，有专家目标速度与超车/跟随指令。论文Figure7实际列出的目标速度只有20/30/40/50/60/70km/h；这是目标速度，不是逐帧实际车速。不能因为名字有Speed就当0–120训练集。公开描述的同Bench2Drive格式也不足以确认新版OCC和free-mask齐全；需要小包核验。没有为此下载约218GB全集。未来真实速度生成的virtual target speed也不能未经部署可得性审查就输入本模型。

[官方代码说明](https://github.com/Thinklab-SJTU/Bench2Drive-Speed)、[论文与分布图](https://arxiv.org/html/2603.25672v1)、图像已留本地 target_speed_pie.png。

3. **highD / exiD：真实高速交互轨迹和场景分布来源。** highD是德国高速车辆轨迹；exiD覆盖出入口、汇入、畅通、拥堵和慢行，并带OpenDRIVE/Lanelet2地图。它们适合筛选速度/车距/TTC/变道、构造场景参数及行为评测，但不提供自车视角连续LiDAR/RGB/OCC。把车辆包围盒栅格化只能得到特权对象占据，不能称为真实可见OCC；轨迹回放也不代表车辆对新候选动作会响应。下载授权与适用范围需要按官方流程处理；本轮未申请或下载。尚未实测100–120分桶数量。

[highD](https://levelxdata.com/highd-dataset/)、[exiD](https://levelxdata.com/exid-dataset/)、[exiD文件格式](https://levelxdata.com/wp-content/uploads/2024/03/exiD-Format_2_1.pdf)。

4. **nuPlan / Nuplan-Occ：OCC与规划数据备选，速度覆盖待核验。** nuPlan官方提供大规模规划日志，但原始传感器只覆盖其中子集。Nuplan-Occ有公开数据入口与10Hz密集体素标签；不能由数据量大推断足够100–120高速片段。其多帧离线重建标签不可直接当作在线可观测历史输入，需区分标签与因果可得观测。本轮没有高速分布证据，不将其列为已验证的120补齐方案。

[nuPlan官方说明](https://nuscenes.org/)、[Nuplan-Occ项目](https://arlo0o.github.io/uniscenev2/)、[数据入口](https://huggingface.co/datasets/Arlolo0/Nuplan-Occupancy/tree/main)。

5. Waymo官方区分Perception、Motion与E2E数据，不能假定三者每段都能一一连接。E2E的相机/轨迹/指令并不自动带OCC；产品在freeway行驶的新闻也不是公开训练数据包含120的证据。本轮不建议先下载全量Waymo迁移任务。

[官方数据组成](https://waymo.com/open/about/)。

## 筛选原则

速度分桶建议0–20、20–40、40–60、60–80、80–100、100–120，120边界在正式实现明确采用闭区间或容差；异常超速另列，不强行裁成120。实际车速与期望速度分别记录。每格同时统计独立episode/道路数、累计秒数、最长连续时长，避免瞬间达到120就被视为覆盖。

交叉维度为巡航、跟车、拥堵启停、汇入、切入、变道、超车、取消、制动，以及交通密度、相对速度、TTC、道路曲率和天气。不是每种机动都要求以120执行；要保留120→低速制动、低速汇入→加速等整个过渡过程，不能按单帧速度把它们截碎。筛选速度只是任务支持分析，不等于安全/专家质量合格。

同步/坐标/单位/模态完整性是硬门槛；unknown与free不能混淆；未来标签可作标签，不能泄漏输入；导航不能由要预测的未来真值临时拼成可部署输入。按母episode/道路/反事实根划分split，保留测试不参与筛选和选模。所有未核实字段标pending，不能默认通过。具体提案写入 configs/data_screening_proposal.json，它不是已启用的训练配置。

## 现有数据还做什么

有用：修正一帧配对后，保留用于低中速交互、拥堵启停、近场动态目标、急刹/变道等行为学习及坐标/缓存/断点回归。不要因最高速度不足删除这些重要行为。旧权重/指标作为旧契约基线保留；正式v3缓存尚未完成，不能把旁路9窗口测试称作正式修复。

不够：当前80–120没有样本、近场OCC无法单独支持远距高速决策，也不能支持候选动作反事实。新增高速数据后使用分层采样/权重，让旧低速数据不淹没稀缺高速段；权重需在训练/开发集确定，不能用测试集调。

## 是否自采

若以本项目CARLA闭环为近期目标，建议定向自采，不必全部重采。先修复并保留旧数据，核验ZOD小样本的补齐价值；对80–120持续巡航/跟车、减速停车、远距切入、侧后方接近目标及反事实分支，用CARLA采集可控同契约数据。真实数据补行为分布，模拟数据补动作可干预与标签完备，两者标明来源，不冒充同域。

自采前先验证传感器frame/timestamp、100–120速度实际达成、地图/车道、unknown/free射线mask和车辆控制能力；不能仅把Traffic Manager目标速度设120就将轨迹认证为专家。先跑60s流水线和几段可审查行为，记录实际速度、碰撞/越界/jerk与控制饱和，再扩规模。失败样本可保留作风险/反事实数据，不能无标签混入优质模仿轨迹。

计算/存储：本轮仅轻量读取7690+1637帧JSON和官方文档，未启动训练、模拟器或大数据下载。自采先实测实时因子r与MB/帧，再估算成本：一小时模拟驾驶墙钟约1/r小时，10Hz有36000帧；单帧0.5/2MB对应约18/72GB（仅容量算例，非本机实测）。先通过小样本与筛选清单，避免先采很多再发现契约仍不对。
