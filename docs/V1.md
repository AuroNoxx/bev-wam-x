# bev-wam-x v1：历史基线、扩展与失败边界

## 版本定义

v1 指 2026-10-22 联合 World-Action Flow 主线之前的系列实验，包含 BEV 确定性世界/轨迹联合学习，及后续候选规划扩展。v1 不是“RGB 版本”的同义词：`models/latent.py::BEVEncoder` 接收 `[B,4,128,128] uint8` 四通道语义 BEV；当前 `models/joint.py` 仍保留其联合模型。

完整旧 Git 快照为 `58fedae458021bb37212442868288f95947288a8`。本地归档在 [archive/v1_legacy_20261024](../archive/v1_legacy_20261024/README.md)，其中 `code/` 保存后来移出的模块，根目录保留共享基础组件。这是部分模块归档，不能直接把该目录当完整独立工程运行。

## 数据和结构

- 在 MetaDrive 中采集四通道语义 BEV、自车状态和专家轨迹；区分训练/验证/测试场景。
- Conv-Stem + Transformer 编码当前/历史观测；潜空间预测配合 VICReg 方差、协方差约束。
- 确定性轨迹模型预测未来 10 个 `(x,y,v,heading)` 路点，由 Pure Pursuit/PID 执行。
- 后续探索 Flow Matching 候选生成、独立动作条件世界预测器与风险头。此路径保留用于历史对照，没有继续作为 v2 的主架构。
- TensorBoard 记录训练，Rerun 记录观测/预测/轨迹，Marimo 组织教学与评测查看。

## 为什么演进到 v2

v1 的候选生成、独立 WAM、风险筛选是分离链路。v2 把未来场景 latent 与轨迹 token 放到同一个交互 Transformer 中联合去噪，研究两者的内部耦合能否改善规划。架构变化是研究假设，不预设收益。

v1 与 v2 的场景、数据和指标并不天然相同，不能把 v1 的路线完成度与 v2 的少量场景到达率直接比较。公平比较需要相同观测、数据划分、场景、控制器周期、训练预算和评价规则。
