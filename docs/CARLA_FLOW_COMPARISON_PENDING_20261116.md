# Pending CARLA data comparison plan (no training launched)

User authorized collecting a few CARLA segments and testing whether Flow improves. Collection owned by carla_build; this document is a preparation plan, not a claim of completed collection or training.

## Required dataset contract
Record collector code/version, CARLA/map/version, episode/route/traffic/weather seeds, controller and interventions, simulation timestamps, local coordinates/ego pose/vector velocity, OCC grid axes/range/resolution/class mapping, unknown/free semantics, visibility and occupancy-generation time support. Future trajectories are supervised labels only. An oracle simulator actor-box grid is not equivalent to causal sensor OCC: explicitly tag it, never present it as on-vehicle perception. Observed collisions/events require sensor coverage; missing remains unknown. Scripted/controller behavior is demonstration, not unique optimal driving.

## Split before creating windows
Whole independently restarted episodes/routes are assigned train/development before overlapping history+future windows are built. Keep complete temporal support inside one episode/split, no duplicate recordings. Same map geometry across different episodes must be disclosed. Prefer a held episode with independently varied traffic seed; if only one episode exists, no generalization claim and collect another or limit to learnability. Any event/route names require actual time-local event evidence. Few segments will not cover all six previous directory scenarios or0-120km/h.

## Compatibility gate
New and old inputs must match history timing, ego state, grid shape/class map/unknown handling and trajectory decoder. Audit units/coordinate transforms and window chronology with roundtrip/synthetic tests. Do not silently interpolate missing truth or turn unknown into free. If new OCC is oracle while old OCC generation is uncertain, a performance difference mixes perception/data-source effects; label the experiment a source-package comparison rather than a pure data-quality effect. A common observable representation is preferred if validly constructible.

## Controlled first comparison
Use the existing small FM architecture(width128,2decoderlayers,4heads,velocity2 integral decoder,current_support world objective unchanged,about0.967M trainable parameters), not a simultaneous architecture upgrade. Fresh paired initialization for two seeds, same noise/time streams, optimizer/precision/learning-rate schedule/batch12, fixed512-update first budget, same checkpoint/evaluation rules. Budget and final number of arms depend on collection size and GPU occupancy; do not start before data contract and matched split are ready.

Preferred three arms if sufficient data: A matched-old-only; B same matched-old pool plus new-CARLA replacement at a prespecified fraction(e.g.25%); C old-only resampling with identical sample count and draw grouping as B to diagnose repetition/coverage effects. All arms same total6144 sample budget, no extra optimization for B. C is redundant if its actual stream equals A; do not run redundant arm. Small collected pool implies repeats, report unique episodes/windows and reuse. Match scenario,initial-speed bins and basic event/trajectory horizons using train data only. If a matched old stratum does not exist, report an unmatched exploratory stratum separately rather than force a causal claim. No post-hoc selecting the favorable mixing fraction.

## Evaluation and interpretation
Evaluate all arms on identical held old routes and separately identical held new episodes. Both all valid windows and a support-disjoint subset; report episode/scenario macro averages and counts, not treating overlapping windows as independent. Fixed pure-noise16Euler and multiple candidates; no target-conditioned inference. Fullt0 dynamics, velocity/position consistency, vector acceleration/jerk, forward progress, near-zero/stagnation and reverse fractions,candidate diversity. Position/velocity imitation error is diagnostic only. Include label metrics so smoother output cannot hide invalid or low-information labels. World prediction versus persistence within each own EMA with mask counts; no cross-EMA absolute ranking. Collision/TTC/rule success remain unknown unless actual matched closed-loop evaluation is performed. Training new simulator segments does not make an offline candidate a closed-loop result.

Stop before training if nonfinite labels, inconsistent axes/timing, unmarked oracle inputs, episode leakage or unclear masks. Save isolated outputs/latest/best, preserve old weights and officialtest. No automatic long training. Await collector evidence and parent coordination.
