# 113M 联合模型容量探针（2026-11-15）

## 执行状态

接管前原联合实验 session 已完成。新增独立 `scripts/probe_joint_occ_capacity.py`，没有修改原模型、训练入口或默认配置。命令为项目 `.venv-train/Scripts/python.exe scripts/probe_joint_occ_capacity.py --run`；语法编译通过，探针退出码 0。结果见 `artifacts/joint-occ-capacity-120m-probe/report.json`，日志见 `logs/joint-occ-capacity-probe.log`。

这是可行性探针，不是正式训练：只加载一个训练窗口，执行三次 AdamW 更新，无 checkpoint 写入；不访问验证或保留测试集。正式训练前必须接入原有 Lightning/VerifiedCheckpointIO 保存恢复链，不可直接把该脚本当长训入口。

## 目标预算

width 768，轨迹 Transformer decoder 10 层、12 头，保留共享 OCC 编码与显式预测未来 latent 融合。总参数 112,960,560，其中 EMA 目标编码器 5,591,058，去掉该目标编码器后 107,369,502。后者仍含辅助语义头，部署可进一步裁剪。当前参数主要扩大在轨迹 decoder，不能据此断言世界表征能力已足够；还需对共享主干/未来 predictor 的容量分配做消融。

## 实测（RX 7900 XT / ROCm，BF16 mixed）

- 物理 batch 1，无梯度累积，学习率 1e-5。
- loss 三步分别 11.41177、5.49558、6.70955。每步随机桥接噪声不同，不作为收敛证明。
- 首步 2.3727 秒含冷启动，后两步 0.08379 / 0.08833 秒。只有两次热态样本，不是稳定吞吐基准。
- 峰值 PyTorch allocated 2.0987 GiB，reserved 2.3965 GiB。
- 单场景 8 候选、16 步积分，纯模型三次热态推理 194.80 / 195.63 / 193.55 ms。不含 OCC 构建、传输、安全筛选、控制，不能达到端到端 100 ms 的当前实验目标，也不代表 Orin 速度。样本太少不报告 p95/p99。
- 替换真实未来标签不改变 actor；更改最后历史帧不改变更早时序输出。代码因果检查通过，不等于源数据无未来融合已认证。
- 所有梯度和输出有限；已有 32 份权重哈希复核无变化。未删除/覆盖权重。

## 已知缺陷及继续顺序

1. 该 batch 1 无跨样本方差正则的有效配对，报告中 variance 为 0。这只适合资源 smoke；正式 JEPA 训练必须 batch >= 2 或实现明确的跨批统计方案。梯度累积本身不会自动修复每个 microbatch 的方差估计。
2. 旧小实验预测 latent 的时间变化被压缩、弱于匹配支持范围持久化基线。先检查动态监督覆盖与同位置特征表征，再比较扩容能否改善，不将大模型当万能修复。
3. 下一步资源测试分别扫物理 batch、候选数 K 和 Flow 步数；预热后增加测量次数，记录 p50/p95/p99/max 与内存，并统计完整端到端时间。候选/步数减少必须同时重新验证行为与安全，不能只优化速度。
4. 引入用户要求的早期云端教练：先建立结构化轨迹/rollout、程序硬指标、教练建议、候选验证、回放更新的最小接口；不是等最终模型训练好才打分。当前未发现明确的项目 cloud-coach 配置，没有调用任何云端 LLM、上传数据或产生 API 费用。供应商、数据范围与预算明确前可继续本地 mock 合同及评分安全测试，但不能将 mock 当实际 LLM 效果。
5. 参照单颗 DRIVE Orin-X，端到端 10 Hz 为实验目标而非安全保证。没有 Orin 实物测试，就只输出算子兼容/导出计划，不能从 AMD 数据换算车端达标。
