# CARLA v2 无高精地图驾驶：Stage 2 → Stage 2.6 架构、闭环与问题报告

更新于 2026-11-22，分支 `codex/v2-mapless-wa`。本文档记录本分支从 Stage 2（本机第 14 轮冻存基线 `models/v2_stage2_nativeC_40k_20261121/stage2.pt`，权重仅存本机不入库）演进到 **Stage 2.6** 的架构修改、云端训练与本机验证结果、平滑控制升级、9 路线闭环表现，以及当前已知边界与 **Stage 3** 规划。模拟器为 CARLA 1.0 / UE 5.8。

## 1. Stage 2.6 架构与感知-规划链路

Stage 2.6 在保留“纯传感 BEV + 粗粒度 SD 导航 + 单向注意力隔离 + 物理控制”主干不变的前提下，将模型升级为 **`Phase26`**（`15,862,810` 参数，Stage 2 为 `15,563,546`）：

| 环节 | Stage 2 基线 | Stage 2.6（最新代码） |
| --- | --- | --- |
| 传感器输入 | 三目裸 RGB（前 `768×448` FOV 100°，左右 `384×224` FOV 110°，gamma 0.5）+ 64 线 360° LiDAR BEV（6 通道，128×128） | 传感器布置与 5 层投影高度表保持一致 |
| 时序记忆 | 单帧推理，无跨帧特征传递 | 传入上一帧 `prev_map_tokens` `(1, 7, 256)` 与连续 IMU/速度推导的 `ego_delta` `(dx, dy, dyaw)`，按 `clip_len=4` 连续片段训练 |
| 导航与指令 | 20/40/60 m 三个 SD 路点 + `Keep/Left/Right` 独热指令 | 新增 `route_instruction`（follow / left / right / straight / roundabout / exit）与 `route_dist`；单向注意力保持严格隔离（切换请求时地图折线/分割/占用/token 差值实测 **`0.0`**） |
| 损失与训练 | 多任务地图 BCE+Dice、占用 BCE+Focal、近 24 m 加权路径 Smooth L1 | 叠加 `curvature_weighted_tangent_loss`（权重 0.5，曲率 `> 0.025` 段权重加倍）；6 桶均衡采样 |
| 物理控制与 LiDAR | 24 m 走廊扫描；未按 `v*t` 对齐占用格；变道用硬分段长度与硬死区 | 38 m LiDAR AABB 预过滤（提速 `3.05x`）+ 远场簇聚类检出；时空对齐 `occ_risk`（`v*t` 窗口）；带符号曲率 + C¹ Hermite 平滑变道接续 + 连续 4 帧漏检容错；Option 3A 巡航 SD 对齐 |
| 实时演示端 | 同步 20 Hz 或主循环偶联相机跟随 | **40 Hz 帧锁独立节拍线程（`FIXED_DT = 0.025`）+ 一帧速度前瞻相机锁定**，与主线程 20 Hz BF16 HIP Graph 解耦 |

## 2. Stage 2.6 云端训练与本机离线验收

### 2.1 Colab L4 训练配置与断点选择

- **数据源**：沿用 Stage 2 的 40,000 帧数据集（`Town12` 训练 22,000 + 独立地理验证 2,000；`Town10HD_Opt` 训练 16,000；**`Town04_Opt` 训练帧为 0**）。
- **片段采样**：按 6 个动作桶组织 `clip_len=4` 连续片段（`straight`: 13,041，`curve`: 19,265，`sharp_curve`: 10,289，`lane_change`: 4,619，`recovery`: 1,423，`exit`: 1,288），每轮每桶均匀抽取 `2,000` 个 clip（共 `12,000` clip/epoch）。
- **训练超参**：Google Colab L4，`bf16-mixed` + `cuda_flash` SDPA + `foreach` AdamW，由 Stage 2 权重热启动；`physical_batch=8`，`gradient_accumulation=2`（等效 batch 16，每轮 `750` updates），lr `2×10⁻⁴ → 10⁻⁵`，实际运行 10 轮 **`actual_updates=7,500`**（耗时 `7,421.0 s`）。
- **选模**：按 `score = 0.25 * lateral_near_m + 0.15 * val_exit_near_m - map_miou` 选择 **Epoch 4（`selected_updates=3,000`，`sha256: b25c574b...`）**。

## 4. 近期工程修复与实时演示端验收

针对实车体验中发现的三个问题，本轮完成以下修改与专项验证：

1. **高速并线二次掉速（`60+ → 50+ km/h`）**：定位到 `SpatialController.lane_tracking` 对收敛偏置与斜率重复累加曲率，且近场硬死区截断（`±0.04 m`）和远端回并段制造了高达 `0.04 m⁻¹` 的虚假曲率尖峰；现已改为带符号 Hermite 端点精确曲率、C¹ 起步/外推融合，并取消单帧虚线闪烁造成的 `horizon` 误刹车。离线 65 km/h 单元测试中，直道并线全程维持 `65.0 km/h`，`R=180 m` 弯道内外并线均 `>= 60.6 km/h`，`R=40 m` 急弯匝道仍正确限速至 `38.1 km/h`。
2. **38 m LiDAR 走廊投影 CPU 耗时**：在 `project_corridor` 前加入严格包含下游阈值（`half_width + 1.0`）的 AABB 筛选。在 60 帧 32,000 点（含空扫描边界）单元测试中 `max_gap_diff = 0`，单步耗时由 `20.03 ms` 降至完整控制 `step()` `6.56 ms`（`3.05x`）。
3. **双窗口 Epic 演示卡顿抽搐**：原全异步模式因传感器帧间隔波动与 TCP/GIL `on_tick` 滞后 1–2 帧导致 `20 Hz` 相机前后抖动；已重构为 [`phase2_demo_async.py`](../phase2_demo_async.py) 中的 40 Hz 独立帧锁后台线程（`FIXED_DT = 0.025`，`settings.synchronous_mode = True`）+ 1 帧速度前瞻原子 `apply_batch`，相机距离误差锁定至 `3.41×10⁻⁷ m`。
   - 长程 `Town04_Opt` `town04_full_ring`（3 圈 `9.21 km` 环线、12 NPC、Epic `1824×1310`）：连续行驶 **`3,402.7 m`**、`4,191` 控制帧、UE5 平均 **`40.89 FPS`**、`0` 碰撞、车道偏移 P95 `0.450 m`。
   - GitHub 发布动图录制同路线实测（附加 `960×688` 录制相机）：`271` 控制帧、行驶 `127.55 m`、UE5 平均 `32.48 FPS`、`0` 碰撞、车道偏移 P95 `0.188 m`，生成 [`docs/images/v2/stage26-epic-demo.webp`](../../docs/images/v2/stage26-epic-demo.webp)（`972×498`, `75` frames, `1.55 MB`）与 [`docs/images/v2/stage26-epic-shot.jpg`](../../docs/images/v2/stage26-epic-shot.jpg)（`1440×738`, `171.6 KB`）。

## 5. 当前已知边界（Stage 2.6 尚未解决的问题）

1. **急弯小半径匝道跨线**：`town04_ramp_exit` 与 `town04_ramp_tight_bend` 在 `road1450` 急弯段（入弯实速 ~19.2–19.7 km/h）仍存在 `60/60` 与 `58/58` 帧压线，需在训练侧补充急弯内衬线/曲率分布并结合控制限速联合排查。
2. **闭环 50 ms 控制周期复核**：`38 m LiDAR` 包围盒 `3x` CPU 加速合入后，上述 9 条同步闭环路线的 `control_p95_ms` 与 `loop_p95_ms` 尚待重跑全套实测确认是否稳态落入 `50 ms`（20 Hz）以内。
3. **无自主超车与舒适度硬门禁**：目前左右变道仅由人工键盘/脚本触发，模型自身尚未学习“前车龟速时自主借道超车”；训练损失和闭环评分也未直接考核变道掉速 `Δv_lc`、方向盘转角峰值/角速度 `|d(steer)/dt|`、急动度 `jerk` 与跟车时距 `THW`。

## 6. 下一阶段：Stage 3 路线图

- **隐空间动作条件世界模型 + 多模态规划（Flow Matching / World Model）**：
  - 相比耗时极高的像素级视频生成世界模型，优先在 **BEV + 空间 Token 隐空间**构建动作条件世界模型，结合 **Flow Matching** 生成带速度规划的多模态时空轨迹 `(x(t), y(t), v(t))`（或候选动作滚动推演），保证在单卡（如 A100 训练、本地 7900 XT 推理）下维持 20 Hz 实时闭环。
- **自主战术变道与借道超车**：
  - 在仿真中系统采集并闭环强化“低速前车识别 → 邻道安全窗口评估 → 加速切出 → 超越汇回”的连续策略样本，使系统不依赖人工点击 `A/D` 即可完成安全超车。
- **拟人舒适度与手感评测体系**：
  - 从闭环 `.jsonl` 轨迹直接提取并卡控：变道最大掉速、方向盘转角分布与角速度 P95、横/纵向加速度与急动度（`jerk` P95）、以及动态跟车时距（`THW`），避免早刹、僵硬降速和机械折线感。
