# 阶段7跨版本复盘与修改建议

本次范围：分析旧阶段7生成消融、融合001–015的报告、当前实现和保留原始数据；没有启动采集、训练、仿真或阶段8/9。历史成绩与失败记录不改写。它是修改建议，不是新验收协议。

核心判断：阶段7多次改进了局部指标，却没有逐层建立“候选可执行 → 行为能完成 → 风险门控不造成死锁 → 世界模型有额外价值”的闭环证据。当前同时存在确定的实现错误、候选/约束不一致、数据覆盖不足及WAM能力不足的证据。继续只改Flow损失、增加参数或补少量起步数据，不能同时解决这些问题。

## 1. 最先需要修的是候选可执行性，而不是风险头容量

当前 `models/navigation_flow.py` 最终返回 `reference + residual`，对(x,y,v,heading)独立加残差。物理参考合规不保证相加后的速度非负，也不保证位移、航向、曲率一致。最终仍靠硬筛剔除。因此“有物理先验”并不是“物理约束已满足”。

015保留记录中，允许左侧超车某时刻所有候选最低速度达到-0.765m/s，阻塞场景达到-1.107m/s。允许右侧超车的Full有532/600步回退，全部没有几何/运动学/许可合格候选；第72步之后风险评估数为0。Full与Zero在该场景的候选和状态相同。这部分失败发生在WAM之前，无法靠风险头重训解决。

终点也有独立问题：CCC/SRS进度已约98.8%/98.3%，但没有原生到达，末段主要被静态包络拒绝。导航只保留5m间隔有效点，未追加精确终点，参考按最后有效点减速；两秒候选全程检查与原生到达区域是否一致尚须实验核实。保留参考轨迹在部分失败时刻能通过静态/运动学离线检查，仅证明候选覆盖存在改进空间，不能据此宣布参考执行必定安全到达。

建议：先对负速度、首点连续性、航向/位置一致性、终点和车道许可做逐项最小复现。若确认直接状态残差是主要原因，版本化比较“有界加速度/转向或曲率残差 → 用实际车型积分 → 输出原约定10点(x,y,v,heading)”；训练与推理使用同一积分和约束。禁止只裁剪v而保留矛盾的xy/heading。旧Flow与方案A继续保留作对照，不能未经对照直接替换。

## 2. 当前是短时轨迹筛选器，完整行为组织仍不足

`IntegratedPolicy.decide` 每次生成8条两秒轨迹，几何选Top4，预测风险，选一条；没有保持目标车道、超越阶段、回归完成条件的行为状态。候选都围绕同一导航参考生成，随机残差间距大于0.1m并不保证包含“安全跟停”“足够持续的借道”“超越后回归”等有用选项。

建议增加明确的行为条件及跨决策状态：巡航、跟车、等待、借道、超越、回归、终点。状态转移依据当前允许输入，带进入/退出条件与滞回；两秒输出与10Hz控制约定不变。每种适用行为先形成可检验的物理候选，Flow负责行为条件下的细化。解析候选与学习候选分别标记，Geometry/Zero/Full共享完全相同候选，保留参考单独驾驶对照，避免把规则能力计作WAM收益。这是建议的新设计，需要单独冻结协议和输入权限。

## 3. 风险数据没有覆盖闭环会访问的状态，阈值又直接控制停车

014接近静止的训练状态全部来自近距离静止前车，缺普通空路静止反例；因此低速/场景捷径是有依据的怀疑，但尚未通过因果消融证明。015增加了正常数据，可正常样本仍集中在单一直道、零背景车流；实际闭环有弯道、其他交通、边车道、终点及偏离后的恢复。

本次从015原始NPZ重新计数：Zero直道800/800步都有几何合格候选，却全部在风险门控后回退；Full同场415步发生相同阶段的回退。既有逐步审计显示Full其中411步涉及出界阈值，某时刻预测约0.0131–0.0141，对应硬阈值0.012829。门控→制动→状态缺少变化→再次拒绝，形成闭环停滞。未执行候选的真实安全性未知，不能据此简单上调阈值。

当前“校准”实际主要是按验证Youden J选择分类阈值，没有完成独立的概率校准；该目标没有约束正常候选可用率、无故停车和驾驶效率。

建议从训练/开发闭环失败前后的真实状态采样，再进行同状态、多动作原生反事实执行。覆盖空路/弯道/临近终点、低速/正常速度、不同前车距离、跟停再启动、左右许可和偏航恢复；包含安全和危险的真实部署候选。独立seed划分训练、选模型、校准和开发验证，避免一批验证数据兼任所有角色。先比较更小风险头与当前3.90M头，检验容量与有效场景数是否匹配。

保留已验证的几何硬约束；学习风险先离线验证校准和误拒，再比较连续风险代价与高置信危险拒绝的组合。未校准时不能宣布低分安全，也不能用强制复活候选消除停车。Top4全部拒绝时，可在预算内逐批评估剩余几何合格候选；每条被选轨迹仍须通过相同检查，且这只是覆盖改进，不是已证明的死锁修复。

## 4. 有几处明确错误，需要先修证据链

1. **001控制接线错误已修复并撤回成绩。** `make_external_env/checked_step`已验证实际动作；不能再引用001作为学习成功。
2. **015分组读取错误仍存在。** 缓存保存`is_flow/is_normal`，`RiskFeatures.fields`却未加载，训练脚本默认全部为Flow、全部非normal。本次重算真实Flow出界正例为训练0/216有效标签、验证0/116；全部24/14出界正例来自诊断轨迹。因此此前“Flow出界AUROC≈0.994”不能成立；总体混合指标可以保留。缺字段应报错，缺正例指标应为null，不能用默认值掩盖。
3. **015短测不能证明动态能力。** “停车再启动”从静止reset开始，所谓刹车动作是[-1,0]，按[steering,throttle]含义实际为转向。危险制动也从静止开始，停着就可能通过。应实际完成加速→正确制动→停车→再起步，并记录入场速度、停止距离、时延和全程原生事件；Full和Zero分别检查。
4. **历史报告有口径混用。** 方案A被称为新盲测但同队列此前用过；旧总报告把97M写为“在15–30M内”；一些参数/阳性数/五臂视频描述已在独立审计更正。应由机器可读结果生成唯一汇总，同时保留原报告与勘误，避免从多版文本挑选最优数字。

修复这些问题不等于性能自动提升，但能避免下一轮再次在错误反馈上调参。

## 5. 大版WAM尚未证明动作后果足够可辨，不能继承小模型成功结论

当前配置加载大版Stage6 seed20261019。其保留评估报告中两个训练种子的动作后果检索准确率均25.78125%，四选一机会水平25%；潜空间预测相对无条件改善3.6653%/4.4948%，低于注册5%。后果差分改善8.9119%/6.0917%通过，错误动作检查也通过，因此不能说WAM完全无动作信息；准确结论是其完整科学门槛未过。

旧风险数据还有事件构成问题：报告统计原生车辆碰撞仅18个、路沿碰撞1463个。高crash AUROC不能自动代表学会动态车辆避碰。015混合风险指标的world碰撞Brier改善虽大，但按seed聚类区间跨零，出界Brier反而变差；Full闭环也没有超过Zero。

建议在候选与数据分布可用后，先做同状态安全/危险动作的后果辨别探针。用实际未来latent的风险探针只能作为训练/验证中的诊断上限，绝不能进入部署输入：若实际未来有增益、预测未来没有，重点修WAM；若两者都没有，先检查表征、标签、风险头与任务是否匹配。可再比较同上下文动作差分/排序辅助目标、动态对象和边界相关token的诊断，逐项检验，而非立即端到端重训。保留相同容量world/zero和匹配无条件对照。参数规模不能代替这些检验。

## 建议只开启一轮有退出条件的修复

| 顺序 | 只改变什么 | 进入下一步前需要看到什么 |
|---|---|---|
| A：证据与接口 | 分组读取、短测动作、配置与汇总；先做最小复现 | 统计与原始标签一致，实际行驶/制动/再起步成立，失败分类可复算 |
| B：候选与行为 | 速度/航向一致、终端和许可核验、适用行为候选与状态 | Geometry先解决现有终点/许可/负速度反例；旧6个导航回归场景均到达，4类交通分别完成约定行为且无原生事故；另有未用于调参的开发seed复核 |
| C：数据与风险 | 采集策略实际访问状态、补部署候选事件正例、独立校准 | 各关键子组有足够独立事件支持；Zero不再造成无故停车，且危险动作检测不恶化；两训练种子闭环复核 |
| D：WAM增益与实时性 | 在完全相同候选/控制/规则上加入未来特征 | Full相对Zero/Geometry的配对收益和安全/效率/停车分别报告；满足现行科学门槛后才谈通过 |

B中的6+4只是旧失败回归检查，不能称科学验收或泛化通过；正式样本量、阈值及置信区间需在新协议中事先冻结。若B失败，停在B，不继续训练风险头；若C失败，不用扩大WAM掩盖；若D没有增益，接受“目前世界模型未改善规划”的结论。

实时性可以先做确定的重复工作消除：Full对同一候选完整调用两次`strict_score`，第二次只是增加风险却重复几何计算。先做结果等价验证再复用几何项，随后测独占机器下的完整决策P95。015的50.33ms为开发观测，尚未证明≤50ms；不能把头部耗时当整套系统。最终仍保留50–100M全系统参数、ROCm/原生SDPA、10Hz和10×0.2s轨迹约定。
