# 阶段7–9融合驾驶改造方案

更新：2026-10-22。依据用户“融合比较好”“先把阶段改了，然后给我一个改的方案”。

状态：**阶段定义已更新，以下实现、采集、训练和验收任务尚未执行。** 阶段7补充报告后停止，阶段8/9仍按阶段确认推进。主目标见 [GOAL.md](../GOAL.md)，任务状态见 [TASKS.md](../TASKS.md)。

## 1. 要解决的问题与保留的路线

目标是在同一套 BEV＋动作条件世界模型闭环中实现导航、跟车、按需超车、回归合适车道、弯道控速与失败恢复。Flow是候选生成方法，WAM负责预测候选后果，控制器负责执行轨迹；规则与模型的贡献分别记录。

本轮10场景pilot：Full到达2/10、平均路线完成54.38%，失败为6次越界和2次超时；Geometry同为2/10到达。IDM到达6/10但有真实导航/车道/交通状态优势。当前神经策略没有导航，评分progress是候选终点自车前向x；这些是已核对的输入和实现差异，不是已经量化的单因素因果结论。证据见 [pilot分析](../artifacts/metadrive_benchmark/pilot_20261022_001/FAILURE_ANALYSIS.md)。

保留四帧128×128四通道BEV、64m尺度、10×(x,y,v,heading)轨迹和0.2s间隔、JEPA/VICReg潜空间预测、Pure Pursuit＋PID、原生ROCm与functional SDPA。无需为本次融合引入强化学习。现有检查点、代码与失败证据不覆盖；新版本建议使用 `artifacts/stage7_integrated/run_<id>/`。

## 3. 输入、数据和权限契约

建议新增 `NavigationProvider` 与版本化数据规范，实施前核对当前MetaDrive源码/API，不假定存在未验证的接口。

- `bev_history`：维持现有四通道及时间轴。动态交通推断来自可用BEV历史，不能悄悄读取模拟器车辆真实速度/意图。
- `ego_history`：保留速度、角速度历史；新增车型参数使用独立字段，声明轴距、尺寸、最大转角的来源和单位。各基线权限一致。
- `route_points_ego`、`route_valid`：仅含当前可获得的任务路线，转换到当前自车坐标系。初始设计可用8个、约5m间距的点，间距/有效范围在开发集验证后冻结；处理终点、重置、缺失与路线切换。
- 导航支路独立编码，不直接覆盖BEV通道。导航点是规划地图/任务输入，不能从专家未来轨迹或实际未来位置反向生成。
- 当前BEV把车道线并入可行驶通道，四通道不足以完整区分虚实线/合法变道区。先审计实际需求：若增加标线/车道许可输入，必须版本化、同样提供给各学习基线，并评估编码器适配；若依赖地图权限，单列地图辅助设置，不能声称BEV自行恢复了合法性。
- 舒适速度由声明的公共速度上限、可用路线/BEV曲率、车距及制动能力共同约束。稀疏导航曲率是近似值，需平滑和有效性检查，不能视为精确道路真值。
- 训练目标仍是实际执行的未来轨迹/潜变量。风险标签为真实分支执行结果与删失掩码，区分固定候选2秒执行与闭环每步重规划后的实际未来。

数据升级建议采用独立schema-3（落地时确认版本号），不修改schema-2含义；旧样本若缺导航，只能保留缺失标记或经可验证的同场景重放生成旁车文件，不能凭空补成完整导航标签。禁止复用已删除schema-1训练数据。

## 4. 模型复用与重训边界

| 模块 | 第一轮处理 | 进一步训练的触发条件 |
|---|---|---|
| BEV编码器 | 复用现有权重并冻结 | 导航轨迹头在新道路验证集仍明显受表征限制，或新增观测通道 |
| 新MSE/ResNet导航基线 | 新增导航支路并训练轨迹头；旧无导航权重单独保留 | 按相同数据和调参规则选择是否微调编码器 |
| Flow轨迹头 | 训练导航条件、必要行为条件与一致的物理先验残差 | 固定输入/数据后仍失败，再试结构修改 |
| WAM | 第一轮冻结复用，不强制加入导航 | 新道路候选后果预测/风险对照在验证集不足，再微调；编码器变更后重建对应潜变量目标并检查兼容性 |
| 风险头 | 在新候选、新场景和原生终止标签下重训与校准 | WAM、编码器或候选分布改变后重新生成特征并验证 |
| 评分器、行为协调与控制器 | 修改逻辑和参数，进行独立控制验证 | 不作为神经训练任务，参数只用训练/验证场景选取 |

特别检查：当前训练残差相对默认运动先验，推理候选叠加不同加速度/转角先验；新版本应让训练/推理的先验定义一致，并明确先验/动作是否作为条件。当前物理先验轴距固定2.47m，控制器读取实际轴距；先固定车型隔离问题，再完成参数化和多车型训练。

## 5. 同一闭环内如何融合行为

候选生成读取BEV历史、自车状态和路线条件；WAM逐候选预测未来；评分考虑路线进度、边界、交通风险、期望速度及平滑度。先保留短时2秒输出，由连续重规划和行为状态保持完成更长时间的超车过程。

建议行为状态为巡航/跟车、准备变道、通过、回归、减速停车/恢复；需要稳定目标关联、道路相对位置、迟滞与超时处理。具体阈值从训练/验证场景确定，不能仅用“目标消失”就判定超车完成。

- 前方畅通：沿路线巡航；弯道到来前控速，检查跟踪误差而非只看规划轨迹。
- 慢车阻挡：先保持安全车距；比较继续跟随和变道候选的风险与实际通行收益。
- 条件允许：只在声明的道路/车道许可、动态间隙和路线要求内超车；安全条件变化时允许放弃。
- 通过后：确认纵向净空和回归间隙，回到适合后续路线的车道；不固定等同于向右或固定横移3.5m。
- 无安全候选：不重新启用被硬约束拒绝的轨迹；选择经检查的减速/制动回退。几何安全与学习风险不可用同一个模糊“拒绝”标记处理。
- 低风险但长期不前进：记录阻挡、让行、导航缺失、候选不足等原因，验证恢复；不能通过放松安全硬约束解决停车。

若保留解析变道候选，MSE以外的相关候选对照共享相同解析库，报告其占比；增加无解析候选消融。对比WAM时必须保持候选相同，不将候选库变化混入WAM增益。行为协调器、限速、回退和实际控制均入日志，禁止隐藏驾驶干预。

## 7. 对照、评测和阈值冻结

学习主对照为相同输入的导航MSE、Flow＋Geometry、Flow＋WAM＋Risk；ResNet＋导航保留为表征基线，匹配world/zero风险头隔离世界预测贡献。IDM只列特权参考。相同场景中固定初始交通、车型、控制器和速度上限；多候选对照使用相同候选预算及解析候选来源，直接回归仍输出单条并明确标注。记录全部训练参数量及调参预算。

分三组证据：

1. **历史诊断复现**：原Stage7与pilot只作历史参考；单独比较原生/宽限越界规则、固定/随机车型、简单/复杂道路，不能合并当新验收。
2. **阶段7开发验证**：专项场景及混合行程，用训练/验证集选权重、阈值、输入和模型。至少两组独立训练种子，不能复用同一权重冒充。
3. **阶段8正式验收**：建议200个预先保留的未见混合场景，0.1/0.3车流分层，另有专项和退化清单；预算在协议中固定。新增测试池属于本项目适配评测，不自动等于原论文/官方排行榜复现。重复训练种子不增加独立场景数。

| 指标 | 定义/处理 |
|---|---|
| 原生到达、安全与cost | 原生终止，分开列车辆/其他碰撞、越界、超时、reward和cost；原生cost不是全部碰撞计数 |
| 路线完成 | 使用导航路线完成率，不用自车前向位移替代，也不当到达率 |
| 效率 | 全部回合时长与结果同时报告；成功回合比较用共同成功子集并声明选择偏差；可预注册失败按时限计的代价 |
| 条件超车 | 预定义慢车与可超车场景、完整通过/安全回归条件，分别报告机会、尝试、完整完成及安全放弃；不奖励尝试次数 |
| 无故停车/死锁 | 结合阻挡和让行条件定义持续停滞；无效导航与确实安全等待独立分类 |
| 舒适性 | 在相同采样/滤波下统计横向加速度、纵向加速度、jerk及转向变化；注明单位和边界处理 |
| 风险校准 | AUROC/AP/Brier、事件支持数、分场景校准与world/zero种子簇配对区间；标签不足不能当通过 |
| 延迟 | BEV就绪到控制输出的完整决策P95≤50ms；另报采集/仿真/日志及真实调度超期；40ms为优化目标 |

原协议生成精度≤1.25×MSE、多样性≥0.1m、运动学≥95%，风险AUROC≥0.75、AP高于prevalence、Brier优于常数，以及world相对zero Brier改善≥5%且差值95%区间上界<0等门槛，不因改阶段被删除或改判。原规划门槛为Full相对MSE和Geometry完成率提升≥2个百分点、区间下界>0且安全率不恶化，两个训练种子均满足。旧head-only P95≤30ms与报告中50ms口径差异继续保留，补充协议必须明确head和完整决策计时边界，不能混用。改变数据后不能直接拿旧无导航MSE数值当新版本阈值参照。

新整体驾驶与专项门槛目前**待冻结**：需明确到达、安全、无故停车、完整超车/回归和舒适性各自的阈值、分母与置信区间。A阶段先登记候选标准，依据训练/验证可行性修订；阶段8测试开始前冻结并记录版本，测试后不得降低门槛。整体驾驶通过与WAM科学增益通过分别出结论，不能用一张综合总分掩盖失败项。

## 8. 实时性实施顺序

先做等价的物理先验批量化，复测输出与端到端决策时间；已有组件探针提示串行先验是明显开销，但探针不代表完整系统已经达标。之后才在验证集比较更少Flow积分步、候选粗筛和特征复用，保留精度/安全对照。

BEV距离场采样不能只检查车身中心代替完整车身占用；Top-K不能先删除唯一安全候选；蒸馏、Cross-Attention等结构修改需要新训练和独立收益证据。单独优化后统一复测，不把组件提速比例简单相加。保留原生ROCm限制，无Orin-X转换、板卡功耗或部署交付。

## 9. 阶段9的对应改造

最低接口校准后冻结权重做零样本迁移；区分模型适配与单位/按键映射校准。新增Ego Provider和Navigation Adapter，与BEV Provider、Control Adapter共同对齐时间、坐标和权限。游戏遥测/内部地图生成BEV的测试标为特权接口测试，画面到BEV另行验证。

目标游戏支持对手车时测试跟车、超车、回归和弯道控速；无相应对象或道路结构则标为未评估。少量适配使用独立游戏训练/验证数据，零样本和适配版在未见赛道/起点/对手配置比较，并保留无世界模型对照、实际回放及视频。
